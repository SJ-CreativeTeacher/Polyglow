# Мастер-промпт для Codex

Скопируй текст ниже в Codex, находясь в корневой папке нового проекта.

---

Создай первую рабочую версию статического веб-приложения **Polyglow** — персонального language learning log и трекера прогресса полиглота с календарём, целями, focus-таймером, фоновой музыкой, аналитикой и мягкой геймификацией.

Смысл бренда: `Poly` — множество языков, `glow` — мягкое сияние видимого прогресса. Основной слоган: **Learn. Focus. Glow.** Визуально прогресс должен проявляться через спокойное свечение воды, лотосов, календарных отметок и звёзд, без чрезмерного неона.

Перед началом работы:

1. Прочитай `AGENTS.md` и `PROJECT_SPEC.md` целиком и считай их обязательными требованиями.
2. Осмотри текущую папку проекта и выполни `git status`. Не удаляй и не перезаписывай существующие пользовательские файлы.
3. Если существует папка `references/`, составь перечень изображений и просмотри их. Считай их прежде всего примерами функций, элементов управления и организации экранов. Используй карту референсов из `PROJECT_SPEC.md`, но не копируй чужой бренд и дизайн буквально.
4. Если доступен поиск в интернете, изучи актуальные лучшие практики только по следующим вопросам: доступный focus-таймер в браузере, надёжное хранение таймера при перезагрузке, доступные интерактивные диаграммы и ограничения autoplay аудио. Используй преимущественно официальную документацию браузеров и библиотек. Кратко перечисли применённые решения и ссылки. Не копируй чужой дизайн.
5. Предложи компактный план реализации по этапам из `PROJECT_SPEC.md` и покажи предполагаемую структуру файлов.
6. Если в требованиях есть действительно блокирующее противоречие, задай один конкретный вопрос. Во всех остальных случаях используй разумные значения по умолчанию из спецификации.

Технические условия первой версии:

- статический сайт, совместимый с GitHub Pages;
- HTML, CSS и модульный JavaScript;
- без backend, регистрации и платных сервисов;
- данные в `localStorage` с версией схемы и миграцией;
- относительные пути ко всем ресурсам;
- полный интерфейс RU/EN без одновременного смешивания языков;
- светлая и тёмная темы;
- адаптивность и базовая доступность;
- музыка включается только после действия пользователя;
- основной визуальный образ — нежный пруд с лотосами и спокойный «сад прогресса»;
- единый набор SVG-иконок, а не эмодзи в качестве интерфейсных кнопок.

Работай по одному этапу за раз. Начни с **Этапа 1 — фундамент**. Не пытайся реализовать весь проект одним монолитным ответом.

Для первого этапа:

1. Создай понятную структуру проекта.
2. Создай адаптивный shell приложения и навигацию по смысловым разделам `today`, `focus`, `calendar`, `goals`, `insights`, `profile`. Их видимые названия бери только из выбранного словаря: Сегодня, Фокус, Календарь, Цели, Аналитика, Профиль для RU либо Today, Focus, Calendar, Goals, Insights, Profile для EN. Никогда не показывай обе версии одновременно.
3. Реализуй дизайн-токены, светлую и тёмную темы, спокойный фон с лотосовой атмосферой и `prefers-reduced-motion`. Возьми из референсов чистую карточную структуру и ясные состояния элементов, но создай самостоятельный природный дизайн.
4. Создай полные централизованные словари русских и английских строк с одинаковыми ключами и рабочее переключение языка. Переключатель размести в верхней панели рядом с управлением музыкой и продублируй в настройках. После выбора весь системный интерфейс, навигация и сопровождение должны отображаться только на выбранном языке. Запрещены смешанные подписи `Русский / English` внутри обычного интерфейса; исключения — сам переключатель, бренд `Polyglow`, слоган, имена собственные и пользовательский контент.
5. Создай безопасный модуль `localStorage` с `schemaVersion`, значениями по умолчанию и обработкой повреждённых данных.
6. Добавь небольшой набор демо-данных отдельно от реальных данных, чтобы интерфейс можно было проверить.
7. Добавь README с простым локальным запуском.
8. Создай отдельный статический каталог языков с ISO 639-1 кодами, названиями RU/EN и флагами стран. Пользователь не должен вводить этот список вручную. Реализуй поиск и локализованную алфавитную сортировку. Флаг показывай только вместе с названием языка; для многострановых языков допускаются несколько флагов или нейтральный языковой значок.

После реализации первого этапа:

- проверь сайт локально;
- проверь консоль браузера;
- проверь переключение RU/EN и light/dark; отдельно убедись, что после выбора на экране нет случайных системных строк второго языка;
- проверь desktop и mobile layout;
- перечисли созданные и изменённые файлы;
- дай мне короткий сценарий ручной проверки;
- остановись и дождись моего подтверждения перед переходом к Этапу 2.

Не выполняй `git push` и не публикуй сайт без моей отдельной команды.

## Промпты для продолжения после проверки

После успешной проверки каждого этапа используй короткую команду:

> Этап проверен, всё работает. Перейди к следующему этапу из `PROJECT_SPEC.md`. Сначала кратко перечисли задачи этапа, затем реализуй их, протестируй и дай мне пошаговый сценарий ручной проверки. Не публикуй проект и не выполняй `git push`.

Если обнаружена ошибка:

> На текущем этапе обнаружена ошибка: [опиши, что произошло и что ожидалось]. Сначала найди причину, не переписывая весь проект. Исправь только необходимые файлы, проверь отсутствие побочных эффектов и дай мне точные шаги повторной проверки.

Перед первой публикацией:

> Проведи финальную проверку проекта по критериям приёмки из `PROJECT_SPEC.md`: бренд Polyglow, функции, localStorage, RU/EN без смешивания системных строк, темы, адаптивность, доступность, музыка, таймер, относительные пути и GitHub Pages. Ничего не публикуй. Сообщи найденные проблемы и исправь только подтверждённые ошибки. После успешной проверки дай мне безопасные пошаговые команды Git для первой публикации.
