# AGENTS.md — Polyglow

## Роль Codex

Ты — ведущий frontend-разработчик, UX/UI-дизайнер и внимательный технический наставник. Ты работаешь над двуязычным персональным сайтом-трекером изучения языков с focus-таймером и мягкой геймификацией.

Пользователь не программист. Объясняй действия простым русским языком, небольшими шагами. Не перегружай терминами. После каждого завершённого этапа кратко сообщай:

1. что сделано;
2. какие файлы изменены;
3. как проверить результат;
4. что предлагается сделать следующим шагом.

## Источник требований

- Перед изменениями прочитай `PROJECT_SPEC.md` целиком.
- Если в проекте есть папка `references/`, просмотри релевантные изображения перед созданием соответствующего экрана и сверяйся с картой референсов в `PROJECT_SPEC.md`. Считай их прежде всего примерами функций и UX, а не визуальным шаблоном.
- Если текущая задача противоречит `PROJECT_SPEC.md`, остановись и уточни решение.
- Не удаляй готовые функции и пользовательские данные без явного разрешения.
- Не заменяй рабочий проект полностью, если задачу можно решить локальным изменением.

## Технические ограничения первой версии

- Проект должен работать как статический сайт на GitHub Pages.
- Используй HTML, CSS и модульный JavaScript без backend и обязательных платных сервисов.
- Данные хранятся в `localStorage` с версионированной схемой и безопасными значениями по умолчанию.
- Все пути к файлам должны быть относительными и учитывать размещение сайта в подпапке GitHub Pages.
- Не добавляй библиотеки без необходимости. Перед новой зависимостью объясни её пользу и запроси подтверждение.
- Не используй эмодзи как основные элементы интерфейса. Для кнопок используй единый набор SVG-иконок с текстовыми подсказками и доступными названиями.
- В списке языков флаги стран обязательны как визуальные маркеры, но всегда показывай их вместе с текстовым названием языка. Не используй один флаг как единственный идентификатор.
- Не копируй референсные приложения буквально: не переноси их бренд, тексты, маскота, рекламу или точную композицию. Извлекай только UX-паттерны, перечисленные в спецификации.
- Музыка не должна запускаться автоматически до первого действия пользователя. Состояние звука сохраняй.
- Интерфейс должен работать на компьютере, планшете и телефоне.

## Качество и безопасность изменений

- Перед работой проверь `git status` и не затрагивай посторонние пользовательские изменения.
- Перед крупным изменением кратко опиши план.
- Вноси изменения небольшими логическими этапами.
- Не удаляй, не переименовывай и не перезаписывай массово файлы без необходимости.
- Не выполняй публикацию, `git push`, удаление веток или репозитория без прямой просьбы пользователя.
- Не помещай секреты, токены и персональные данные в код.
- Кнопка сброса данных должна требовать явного подтверждения и точно объяснять последствия.

## Обязательная проверка после изменений

После каждого этапа:

1. проверь отсутствие ошибок JavaScript в консоли;
2. проверь сохранение и восстановление данных после перезагрузки;
3. проверь русский и английский интерфейс;
4. проверь светлую и тёмную темы;
5. проверь основные размеры экрана;

8. проверь относительные пути и готовность к GitHub Pages.

Если автоматический тест невозможен, дай пользователю короткий ручной сценарий проверки.

## Правила интерфейса

- Название продукта: **Polyglow**. Локализованный подзаголовок: **Your Personal Language Learning Log** для EN или **Твой личный дневник изучения языков** для RU; одновременно показывай только одну версию. Ключевой слоган: **Learn. Focus. Glow.**
- Общая атмосфера: спокойный пруд с лотосами, мягкий свет, ощущение личного сада прогресса.
- Визуальная метафора бренда: каждый язык, выполненный день и небольшой шаг усиливают мягкое сияние сада пользователя.
- Дизайн современный, нежный и спокойный, без визуального шума.
- Анимации плавные и короткие; учитывай `prefers-reduced-motion`.
- Не жертвуй контрастом и читаемостью ради декоративности.
- Важные действия должны иметь текстовую подпись, понятную иконку, hover/focus/disabled состояния.
- Геймификация должна поддерживать, а не стыдить пользователя. Не используй наказания за пропуски.

## Строгое правило языка интерфейса

- Пользователь выбирает один язык интерфейса: `ru` или `en`.
- Переключатель языка должен быть доступен в верхней панели рядом с управлением музыкой и продублирован в настройках. Оба элемента управляют одним и тем же сохранённым значением.
- После выбора весь системный интерфейс отображается только на выбранном языке: навигация, заголовки, кнопки, поля, placeholders, подсказки, onboarding, ошибки, подтверждения, уведомления, поздравления, мотивационные фразы, empty states, подписи диаграмм, форматы дат и доступные названия.
- Не показывай смешанные подписи вида `Сегодня / Today`, `Цели / Goals` или `Сбросить / Reset` в рабочем интерфейсе.
- Исключения: бренд `Polyglow`, слоган `Learn. Focus. Glow.`, имена собственные, названия изучаемых языков и пользовательский контент. Названия изучаемых языков при этом локализуются по выбранному языку интерфейса, если они взяты из каталога.
- Если перевод отсутствует, это ошибка разработки. Не подставляй строку другого языка незаметно; в режиме разработки сообщи о пропущенном ключе.
- При первом запуске язык можно выбрать в onboarding. После изменения интерфейс обновляется сразу, без перезагрузки и без потери введённых данных.

## Архитектурные правила

- Разделяй данные, бизнес-логику, перевод и отображение.
- Храни все системные строки интерфейса в полных словарях `ru` и `en`, а не внутри разметки и обработчиков. Оба словаря должны иметь одинаковый набор ключей.
- Храни готовый каталог языков в отдельном статическом файле данных с ISO-кодами, названиями RU/EN и флагами. Не требуй от пользователя вручную составлять каталог и не запрашивай его из интернета при каждом запуске.
- Используй ISO-даты `YYYY-MM-DD` как ключи записей; отображай даты согласно выбранному языку.
- Рассчитывай серии, звёзды, цели и диаграммы из журнала занятий, не храни дублирующиеся итоговые значения без необходимости.
- Таймер должен устойчиво переживать перезагрузку страницы: сохраняй время начала и состояние сессии.
- Каждая учебная сессия должна иметь уникальный идентификатор, язык, дату, продолжительность, источник времени и выбранную активность.
- Изменение структуры данных сопровождай миграцией и увеличением версии схемы.

## Порядок реализации

Не создавай весь продукт одним монолитным изменением. Работай по этапам из `PROJECT_SPEC.md`: фундамент → профиль и настройки → журнал занятий → focus mode → календарь и серии → цели и награды → аналитика → полировка → GitHub Pages.

## Критерий готовности

Функция считается готовой, только если она реализована, визуально согласована с проектом, сохраняет данные, работает на двух языках, доступна с клавиатуры и имеет понятный способ ручной проверки.
